# 云驿 常见问题排查与解决

> 本文件列出用户在使用云驿时可能遇到的所有常见问题，按"症状 → 原因 → 解决"排列。
> 大部分问题可通过命令行直接解决，命令均已附上，点击右上角复制按钮即可。
> 90% 的问题集中在 **启动失败** 和 **网络入站** 两类，优先排查。

---

## 一、启动 / 显示问题

### 1. 双击 exe 没反应，或报"缺少 DLL"
- **原因**：`libssl-4-x64.dll` / `libcrypto-4-x64.dll` / `WebView2Loader.dll` 不在 exe 同目录
- **解决**：整个 `dist/pkg` 文件夹完整解压，不要单独拷 exe；先检查 DLL 是否齐全：

```bash
# 检查当前目录这三个 DLL 是否存在
dir libssl-4-x64.dll libcrypto-4-x64.dll WebView2Loader.dll
```

### 2. 弹窗"未检测到 WebView2 运行时"
- **原因**：系统缺 Edge WebView2 运行时（Win10 早期版本常见）
- **解决**：用 winget 一键安装，或点弹窗里的链接下载：

```bash
# 用 winget 安装 WebView2 运行时（Win10/11 自带 winget）
winget install Microsoft.EdgeWebView2Runtime
```

### 3. 打开后白屏 / 显示 "yunyi.html not found"
- **原因**：`webview/` 文件夹不在 exe 同目录，或从错误目录启动
- **解决**：确认 webview 文件夹存在；用右键 →"发送到桌面快捷方式"，不要自己改快捷方式路径：

```bash
# 检查 webview 文件夹内容是否齐全
dir webview
```

### 4. 窗口没图标
- **原因**：`icon.ico` 缺失
- **解决**：把 icon.ico 放到 exe 同目录：

```bash
# 检查 icon.ico 是否存在
dir icon.ico
```

### 5. 打不开软件但任务管理器有进程
- **原因**：上次没正常退出，后台残留进程占住端口
- **解决**：强制结束所有云驿进程后重开：

```bash
# 强制结束 GUI 和后台进程
taskkill /F /IM 云驿GUI.exe
taskkill /F /IM 云驿.exe
```

### 6. 窗口缩放异常 / 拖动卡顿
- **原因**：Win10/11 显示缩放（DPI）与程序不匹配
- **解决**：exe 右键 → 属性 → 兼容性 → 更改高 DPI 设置，勾选"替代高 DPI 缩放行为"

## 二、网络连接问题（最常见）

### 7. 打开软件一直加载 / 提示 127.0.0.1:8080 无法访问
- **原因**：后台中继进程（云驿.exe）没起来，或 8080 端口被占用
- **解决**：
  1. 确认 `云驿.exe` 在 exe 同目录
  2. 先结束残留进程（见第 5 条）
  3. 查 8080 端口被谁占用并结束它：
  4. 杀毒软件可能拦截后台进程，把云驿加入白名单

```bash
# 查看谁占用 8080 端口（最右侧数字是 PID）
netstat -ano | findstr 8080
# 结束占用进程（把 <PID> 换成查到的数字）
taskkill /F /PID <PID>
```

### 8. 右上角一直红点"服务器未连接"
- **原因**：`mc.qinnai.xyz:2885` 连不上（后端离线 / DNS 解析失败 / 断网）
- **解决**：先测 DNS 和连通性判断是哪种：

```bash
# 检查域名能否解析
nslookup mc.qinnai.xyz
# 测试服务器连通性
ping mc.qinnai.xyz
```

> **注意**：红点只影响在线状态显示，**不影响创建房间和联机功能**。

### 9. 朋友连不上我的服务器
- **原因**（按概率排序）：
  1. **手机热点 / CGNAT**（运营商给内网 IP）→ 无法作为中继，只能加入别人
  2. **路由器 IPv6 防火墙拦截入站** → 路由器后台放行 40000-41000
  3. **Windows 防火墙拦截** → 用下方命令手动放行
  4. **房主端没保持运行** → 房主必须一直开着软件
- **解决**：先判断网络类型，再放行防火墙：

```bash
# 查看本机 IP（IPv6 是否为 2408:/2409: 等全局地址，IPv4 是否为内网段）
ipconfig

# 放行 Windows 防火墙入站端口（必须以管理员身份运行命令行）
netsh advfirewall firewall add rule name="云驿" dir=in action=allow protocol=TCP localport=40000-41000
```

> **网络类型速查**：IPv4 为 `192.168.x` / `10.x` / `172.16-31.x` 是内网；`100.64.x - 100.127.x` 是运营商 CGNAT（无法入站）；IPv6 为 `fe80:` 开头是仅本地链路。

### 10. 创建房间时提示"连接服务器失败"
- **原因**：GUI 里的中继进程没起来（同第 7 条）
- **解决**：按第 7 条排查：

```bash
# 检查 8080 端口是否被占用
netstat -ano | findstr 8080
```

### 11. 输入连接码后一直转圈，最后超时
- **原因**：对方网络不可达 / 房主掉线 / 连接码输错
- **解决**：确认连接码完整（房间号-端口-代码三段）；让对方重启房间再试；测对方地址连通性：

```bash
# 测试对方服务器地址连通性（把 IP 换成实际地址）
ping <对方IP>
```

## 三、房间 / 中继功能

### 12. 房间突然消失
- **原因**：45 秒无心跳，房间被自动清理（房主断网或后台进程被杀）
- **解决**：保持房主端运行；重新创建房间

### 13. 提示"房间已满"
- **原因**：单房间最多 10 人
- **解决**：等有人退出，或换房间

### 14. 提示"端口池已满"
- **原因**：1001 个端口全用完（个人使用几乎不会出现）
- **解决**：关闭一些房间释放端口：

```bash
# 查看端口池范围是否被其他程序占用
netstat -ano | findstr 4000
```

### 15. 加入时提示"TLS 握手失败 / 协议版本不匹配"
- **原因**：房主和加入者用了不同版本的软件
- **解决**：所有人更新到同一版本

## 四、设备信息卡片

> 主页左侧卡片显示本机硬件配置 + 实时占用率（CPU / 内存 / 硬盘百分比，每 3 秒刷新一次）。

### 16. 设备信息空白或显示不全
- **原因**：采集函数执行时崩溃（早期版本 bug，已修复）
- **解决**：更新到最新版；不影响其他功能

### 17. CPU / 内存 / 硬盘显示不对
- **原因**：注册表读取失败、单位换算，或 SMBIOS/SetupDi 解析不完整
- **解决**：仅影响显示，重启软件或更新版本

### 18. 实时占用率不刷新
- **原因**：后台推送线程异常（罕见）
- **解决**：重启软件；不影响其他功能

## 五、其他

### 19. 主题面板选项点不动
- **原因**：WebView2 渲染 bug（历史版本）
- **解决**：更新版本

### 20. 背景图/背景色切换无效
- **原因**：`bg.jpg` 缺失，或背景色在背景图开启时不生效
- **解决**：确认 `bg.jpg` 存在；背景色只在关闭背景图时有效：

```bash
# 检查背景图是否存在
dir bg.jpg
```

### 21. 退出软件后，后端控制台仍显示"在线"
- **原因**：心跳超时清理有延迟（默认约 25-45 秒），退出后不会立即下线
- **解决**：等待 1 分钟刷新即可；属正常现象

### 22. 日志 / 流量数据不断增长占满磁盘
- **原因**：`logs/` 目录无限写入，无日志轮转
- **解决**：定期清理 logs 文件夹：

```bash
# 清空日志目录（注意：删除后不可恢复）
del /q logs\*.log
```

## 六、P2P 直连（NAT 打洞）

> 房主与玩家都运行云驿，用"P2P 直连"页同房间码打洞，直连成功后不经中继。打洞失败会自动退回中继，属正常降级。

### 23. P2P 页提示"无法连接本机 P2P 服务（8081）"
- **原因**：房主进程（HTTP 8081）没起来，或端口被残留进程占用
- **解决**：确认云驿在正常运行；结束残留进程重开：

```bash
# 查看谁占用 8081（最右侧是 PID）
netstat -ano | findstr 8081
# 结束占用进程后重开云驿
taskkill /F /PID <PID>
```

### 24. P2P 状态一直停在"获取公网候选…"
- **原因**：STUN 服务器（`mc.qinnai.xyz:3478`，UDP）不可达，或 UDP 被防火墙拦截
- **解决**：确认后端在线、UDP 可达：

```bash
# 后端在线则能解析并 ping 通（打洞还需要 UDP 3478 可达）
ping mc.qinnai.xyz
```

### 25. P2P 状态"打洞失败" / 一直"打洞中…"最后失败
- **原因**：一方是严格/对称 NAT，路由器拦截 UDP 入站，或两端 IP 版本不互通（一方只有 IPv4、一方只有 IPv6）
- **解决**：打洞失败自动退回中继，改用普通房间加入即可；检查路由器是否放行 UDP

### 26. P2P 提示"未发现对端，请确认对方已加入同一房间"
- **原因**：房间码输入不一致，或对端还没点开始
- **解决**：双方确认房间码完全一致、都点了"开始打洞直连"

### 27. 房主 P2P 提示"无法连接本地 MC 服务器"
- **原因**：本地 MC 服务器没启动，或端口填错
- **解决**：先启动 MC 服务器，确认端口（默认 25565）填对

### 28. 玩家 P2P 提示"本地端口监听失败"
- **原因**：25565 端口被占用（MC 客户端还开着 / 其他程序）
- **解决**：P2P 页换一个空闲端口：

```bash
# 查看 25565 被谁占用
netstat -ano | findstr 25565
```

## 七、问题解决页与主题

### 29. 问题解决页显示"无法加载问题解决文档"
- **原因**：`webview/TROUBLESHOOTING.md` 缺失，或从错误目录启动
- **解决**：确认文件存在：

```bash
dir webview\TROUBLESHOOTING.md
```

### 30. 主题设置重启后没有恢复
- **原因**：WebView2 的 localStorage 被清理（手动清缓存 / 数据目录被删）
- **解决**：重新设置主题即可；不要用隐私模式启动

## 快速排查顺序

遇到任何问题，按以下顺序排查：

```
1. 杀毒/任务管理器里是否残留云驿进程？
     → taskkill /F /IM 云驿GUI.exe && taskkill /F /IM 云驿.exe
2. exe 同目录是否有 webview/ 文件夹和三个 DLL？
     → dir webview && dir *.dll
3. 是否从桌面快捷方式启动？
     → 确认快捷方式没改过路径
4. 打开软件一直加载？
     → netstat -ano | findstr 8080
5. 朋友连不上？
     → ipconfig 判断网络类型，再 netsh 放行防火墙
6. P2P 打洞失败？
     → netstat -ano | findstr 8081 确认房主进程，再 ping mc.qinnai.xyz
```

**一句话总结**：90% 的问题集中在第 7 条（后台进程/端口冲突）和第 9 条（CGNAT/防火墙），这两条解决好了基本不会再遇到别的。
